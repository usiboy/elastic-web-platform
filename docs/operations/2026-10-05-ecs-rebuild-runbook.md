# 既有 ECS 清退与新平台重建预案

**状态：计划，不是操作记录。** 用户允许现购 ECS 上已开发的旧平台被完全卸载/打破；具体停机/卸载应在确认实例身份、现有网站、数据所有者及恢复点之后分步执行。本文没有执行云端删除、停机、清库、证书切换或域名变更。

## 1. 为什么允许清场仍需盘点

旧项目记录显示原 ECS 曾同时承担原独立网站 HTTPS（80/443）、开发者控制台回环端口、PostgreSQL、K3s/镜像与证书。用户授权重建**旧平台**并不等于这些流量/数据可盲删。重新使用 ECS 前逐项确认：实例 ID/地域/磁盘与云盘关系、域名/DNS/安全组、监听端口与入站、服务/容器/定时任务、DB 和对象/卷/证书、GitHub App 安装与 webhook 回调、上游绫通是否仍调旧入口、其他站点是否仍由同一实例承载。现场事实优于历史文档。

| 资产 | 行动前必须证明 | 清退条件/回退 |
|---|---|---|
| 原网站与域名 | 当前访问量、域名指向、站点责任人、证书有效期及能否停止 | 若与旧产品无关，先迁出/获得网站所有者的停用决定；确认探针和流量切换后才能卸载其入口 |
| PostgreSQL/本地卷 | 库列表/业务所有者、数据留存期限、可恢复备份与对象索引 | 快照/导出、在隔离环境实际恢复并核对行数/校验和；新库用新身份建立，绝不从旧库直接升级 |
| Git 安装/密钥 | App 所有者、回调和短期令牌位置、是否与其他应用共享 | 回调解绑与凭据轮换/撤销要在新入口核验后；私钥不复制到新项目仓库 |
| 云盘/镜像/K3s | 挂载、容量、快照、非旧平台业务是否共用 | 确认仅旧平台使用后才移除；保留恢复点和预计保留时长 |
| 控制台/旧客户端 | 现有用户、绫通适配器和调用路径 | 通知停用窗口，记录不可用窗口与回退 DNS/入口；新产品不能静默继承旧身份/额度 |

## 2. 清退分段

1. **只读取证：**核实云账号与实例 ID、服务列表、路由配置、真实访问日志摘要、数据盘归属、DNS 和 Git webhook；产出 `docs/operations/ecs-inventory-<date>.md`（只记 ID/摘要，不写 Token）。确认旧服务与原站点各自责任人。
2. **冻结与恢复点：**暂停旧服务写入/旧 webhook，并告知受影响用户；对可恢复数据库、卷、证书/配置、对象和路由做受保护备份。先在隔离环境演练恢复，再记录快照 ID、加密与保留期，备份不进 Git。
3. **停旧服务：**先停止旧候选流量和后台 Job，读回外部请求/绫通调用停止，再下线旧控制服务与网络路由。若仍保留原网站，不动其 80/443 Host 和证书；若已批准一并停用，再按站点专门退场计划处理。
4. **回收/重装：**确认冻结数据可恢复后才清理旧容器、K3s、数据库实例和本地镜像/缓存；重装使用新的服务账号、数据库、命名空间和配置，不拷贝旧 Operator Token、GitHub App PEM、签名私钥或 `data/`。每个删除动作单列对象 ID，dry-run/停机观察后再做，不用宽泛的整盘删除脚本。
5. **建新与切流：**按[路线 P1–P6](../plans/2026-10-05-rebuild-roadmap.md)先在独立测试域验证 Git→真实 Preview→Production，最后才给正式域名切向新入口；必须保留旧 DNS/入口回退值、证书与健康探测，直到验证窗口结束。

**停止条件：**找不到可恢复备份、原站点仍有未经批准的生产访问、资源归属不明、新入口证书/DNS/沙箱不就绪、两租户或回滚失败时停止清退或切流。若停旧后新平台未就绪，恢复原 DNS/入口及原数据快照；对停写期间差异做核对，不能仅以服务进程 `200` 宣称恢复。

## 3. 单 ECS 与资源预算

既有 ECS 规格/磁盘余量/区域及闲置成本都需新现场采样。建议清场后其职责仅为**控制面和单区域入口（开发起步）**；陌生租户的 `npm install`、Vite/Next 编译及 SSR 函数不与平台控制 DB/密钥同宿主裸跑。R1 至少另有隔离 Builder 工作资源，R2 增加独立 Runtime Worker；可选择经过验证的外部沙箱服务替代自建节点，但需有网络/硬磁盘/回收/费用证据。域名、对象存储与数据库可由独立托管服务提供，成本确认后才采购。单 ECS 故障仍会影响入口，不提供高可用 SLA。
