# testA/testB 短期 OIDC 身份与同 ECS `runsc` 自动构建实测

**日期：2026-10-09。范围：**用户允许修改 `usiboy/testA`、`usiboy/testB` 的 GitHub Actions 工作流与 OIDC 信任配置。本轮仍为原 ECS、内部 CA/精确测试 Host、两份批准的**公开测试仓库**与合成静态页面；没有将本机 GitHub App PEM、纤莉秀真实库或快麦会话上传 ECS。

## 身份和交付路径

- 两仓库分别增加 `.github/workflows/ewp-preview.yml`：`main` push 上 checkout、Node22、`npm ci --ignore-scripts`、真实测试/构建成功后才向 GitHub 申请受众分别为 `ewp-ecs-testA`/`ewp-ecs-testB` 的短期 OIDC JWT。权限限制为 `contents: read`、`id-token: write`。GitHub Actions 的 `GITHUB_TOKEN` 仅在当前 Job 的内存中作为**临时单仓库只读身份**发送给新 API；没有在 ECS 文件、数据库、镜像、工作流日志持久化 Token，也没有将 App PEM 移动到 ECS。两仓库仅配置公开 CA **证书**的 Actions Secret `EWP_INTERNAL_CA_PEM`，没有私钥。Actions 对 `114.55.237.62:443` 指定精确 SNI/Host `console.ecp.lingtong.com` 并使用该 CA 验证，未用 TLS `--insecure`。
- 平台验证 GitHub OIDC RS256/JWKS、`iss`、分别固定的 `aud`、repo/owner **数字 ID**、工作流路径、`main`、push、提交 SHA、运行 ID/尝试号和时间窗。真实 Actions 的定制 `sub` 实际为 `repo:usiboy@1673411/testA@1404606559:ref:refs/heads/main`（B 同理）；最初按默认 `repo:usiboy/testA:...` 验收返回 401，经仅修正**精确 ID 形式**后 A 重跑通过，没有放宽成通配符。数据库 `022_actions_oidc_pilot.sql` 限定 OIDC 事件来源及唯一 Run/Attempt 回执，重放不能再次造候选；A 身份访问 B、已撤销绑定、错工作流/受众及签名篡改均在本机 PostgreSQL/Race 测试拒绝。
- 仅 OIDC 声明不足以证明上传的源码：ECS 持 Job 临时仓库令牌**独立**调用 GitHub API，检查其授权仓库列表仅有目标 Repo ID、当前 `main` SHA、固定 Git Commit/Tree/Blob 元数据和每个 Blob 内容的 Git 对象 SHA-1；从这些字节构建受限源码归档，后端只落摘要/来源/一次性状态。Repo 令牌被 GitHub 结束 Job 后撤销，不进入 Builder 容器。全新提交 `fdfe8c7`/`3aa34c0` 曾被 Mac 侧无凭据公开 API 真核源；ECS 公开 API 后因 **60 次/小时限额**达到 0，改用上述经 OIDC 约束的 Job 临时仓库令牌后 B 新提交回执通过。
- 仅两项目的受限 timer `ewp-actions-builder-pilot-20261009.timer` 自动发现 OIDC 来源、签发一次性作业；独立 `PrivateNetwork=yes` Builder daemon、固定镜像/离线依赖缓存、`runsc --network none`、CPU/内存/PID/总作业时限、每项目 64 MiB `tmpfs` 输出硬限运行 Vite，再核输出归档、一次性签名交接与私有 Host。**同 ECS 临时密钥不是独立信任域签名**；不用于陌生仓库或共享 SaaS 准入。失败作业立即写稳定 `build_failed`，签名迟到回放被拒绝，原别名完全不变。

首次 A/B 自动构建出现 `build_failed`，不是对源码成功的证明。根因经对比同一脚本在 root 与 systemd 中运行确认：新 Builder unit 的 `PrivateTmp`/`ProtectHome` 使挂载处在**私有 mount namespace**，第一次 64 MiB tmpfs 虽在 unit 内创建却未出现在独立 Docker daemon 的宿主挂载视图，unit 结束后甚至消失。保留隔离 unit 属性，但只用 `nsenter -t 1 -m` 在 PID1 宿主挂载命名空间准备受核输出卷并执行限定脚本；真实 B 卷持久可见 64 MiB，随后两项目 `runsc` 输出和 Preview 验收通过。失败记录仍保留供审计，不冒充第一次就成功。
